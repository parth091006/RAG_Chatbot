2. IMPLEMENTATION AUDIT
=======================

2.1 Parser
----------
File: src/rag/ingestion/parser.py

The parser:

- Uses PyMuPDF block extraction.
- Removes selected repeated headers and footers.
- Splits blocks at the page midpoint.
- Creates left and right block regions.
- Scores regions using text length, width, and text density.
- Treats the higher-scoring region as primary.
- Treats the other region as secondary.
- Returns primary blocks followed by secondary blocks.

The parser does not semantically identify diagrams. It uses geometric
classification. A genuine two-column text page could therefore have one text
column classified as secondary content.

2.2 Pipeline
------------
File: src/rag/pipeline.py

PhaseOneRAG currently loads pages with pypdf directly. It does not call the
layout-aware parser in src/rag/ingestion/parser.py.

The pipeline:

- Supports bow, tfidf, and semantic representations.
- Uses fixed 250-word chunks with 50-word overlap by default.
- Uses DenseRetriever over the selected representation.
- Uses the deterministic generator.
- Does not use cross-encoder reranking inside answer_question().

The stated TF-IDF -> top-10 -> cross-encoder -> top-5 flow is implemented by
the dedicated reranking scripts, not by PhaseOneRAG globally.

2.3 Chunking
------------
File: src/rag/chunking/chunker.py

The current baseline uses fixed-size page-aware chunks:

- chunk size: 250 words
- overlap: 50 words

Chunk IDs are position-based:

doc_self-attention-transformers-2023_chunk_018

Both chunk_pages() and section_aware_chunks() generate chunk IDs using the
same sequential numbering pattern.

2.4 Retrieval
-------------
Files:

- src/rag/retrieval/dense.py
- src/rag/retrieval/sparse.py
- src/rag/retrieval/hybrid.py
- src/rag/embeddings/embedder.py

Dense retrieval uses cosine similarity.

Sparse retrieval uses a local BM25 implementation.

Hybrid retrieval combines dense and BM25 rankings with Reciprocal Rank Fusion.

Embedder supports:

- bow
- tfidf
- semantic sentence-transformer embeddings

2.5 Reranking
-------------
File: src/rag/retrieval/reranker.py

The default reranker is:

cross-encoder/ms-marco-MiniLM-L-6-v2

It receives candidate document texts and returns the highest-scoring top-k
candidate indexes.

2.6 Generation
--------------
File: src/rag/generation/generator.py

The current generator is deterministic and extractive. It is not an LLM.

It selects up to three sentences using:

- question-term overlap
- question-term coverage
- context priority
- duplicate suppression

The prompt interface exists for future compatibility, but the prompt is not
sent to an external model.

copied from noisy evidence can still receive a score of 1.0.

10. FINAL AUDIT CONCLUSION
==========================

The project state is mostly as described, with these corrections:

1. PhaseOneRAG uses pypdf, not the layout-aware parser.
2. Only the reranker evaluation scripts implement the requested TF-IDF,
   top-10, cross-encoder, top-5 flow.
3. evaluate_retrieval.py defaults to BoW, not TF-IDF.
4. The two question files differ in four relevant_chunks entries.
5. Chunk IDs are position-based and can become invalid after extraction changes.
6. inspect_pdf_blocks.py has a pre-existing syntax error.
7. The current test baseline is healthy: 17 tests passed.

Recommended next phase boundary:

First make the actual baseline use the layout-aware parser while preserving
primary-plus-secondary content by default. Then add an explicit primary-only
representation option. Keep all experiment outputs in new files and do not
modify either question or ground-truth JSON file automatically.
